# Server on Effect v4 rc, pinned exactly; SQLite through effect/sql without an ORM; SSE with replay; a types-only Client

The server is TypeScript on Node 24, because the Pi SDK is TypeScript and runs in-process (ADR-0001). It is built on Effect v4 (`effect` plus `@effect/platform-node`), pinned exactly to `4.0.0-rc.118`, and the whole `@effect/*` family is held to that version with pnpm overrides. The overrides are needed because the v4 release candidates ship weekly with breaking changes (rc.118 renamed every `effect/unstable/*` import path), and the packages depend on each other through caret ranges. We chose v4 over the stable v3 (3.22) because v4 merges `@effect/platform`, `@effect/sql` and `@effect/experimental` into `effect` itself, and it ships three things convo needs that v3 lacks: native SSE in `HttpApi` (`HttpApiSchema.StreamSse`, whose "events" mode sends `id:` lines), a static file server with SPA fallback, and a SQLite client on Node's built-in `node:sqlite`, so there is no native addon to build. On v3 we would have to build all three by hand and still face a v3→v4 migration later. Storage uses `effect/sql` with Effect Schema-typed queries (`SqlSchema`) and `SqliteMigrator` behind a repository service, and no ORM. We considered Drizzle and rejected it, because no Drizzle setup works with current Effect v4. `@effect/sql-drizzle` supports only v3, and only drizzle below 0.50. Drizzle's own v4 driver (`drizzle-orm/effect-sqlite-node`) crashes at runtime with the current rc when installed from the tagged `drizzle-orm@rc`. The only working combination is effect `4.0.0-rc.117` with an untagged Drizzle preview build, whose type declarations break on rc.118, so it would also freeze our Effect upgrades until Drizzle catches up. Without an ORM we keep one dependency family that we can upgrade freely. Live Session transcripts and Task updates go to the Client as Server-Sent Events. Each event carries its sequence number as the SSE `id`, so a reconnecting `EventSource` resumes from `Last-Event-ID`, and the server replays the stored events it missed. The web Client imports only *types* from the `api` package, never Effect at runtime, which keeps Effect's rc churn out of the browser bundle. A Vite plugin enforces this by failing the build on any runtime import of `effect`, `@effect/*` or `@convo/api`. TypeScript is pinned to 6.0, the newest line `@effect/language-service` supports (TypeScript 7 would need `@effect/tsgo` instead). The costs: we track a moving rc by hand, we hand-write SQL for a handful of tables, and the Client re-declares its fetch calls instead of using a generated Effect client.
